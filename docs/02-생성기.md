# 2단계 — 생성기

## 목표

원장 하나에서 운영용 설정과 문서용 표가 전부 나오고, 원장의 실수는 생성 전에 막힌다.

---

## 뭐가 돌아가나

- **`tools/netgen.py`** — 점검 + 생성. 포트 배정(리프 49=spine1, 50=spine2, 47=방화벽, 1~46=서버)과 IP 계산을 여기서 한다
- **`templates/`** — Jinja2(빈칸 채우기 양식). 리프 FRR, 리프 데이터플레인 스크립트, 스파인 FRR, netplan, 랩용 4종

### 생성물 (`build/`)

| 파일 | 내용 |
|---|---|
| `configs/<스위치>/frr.conf`, `interfaces.sh` | 스위치 설정 (포트명 EthernetN) |
| `servers/<서버>.netplan.yaml` | 서버 NIC, LACP bond |
| `ipam.csv/md`, `cabling.csv` | IP 78개, 케이블 87개 |
| `netbox/*.csv` | NetBox 일괄 입력용 |
| `monitoring/*.json` | Prometheus 수집 대상, 기대 BGP 세션 수 |
| `ansible/hosts.yml` | 인벤토리 |
| `report.md`, `fw-policy.md` | 과가입비·전력, 정책 표 |

### 띄우는 법

```bash
pip install pyyaml jinja2
python tools/netgen.py build
```

### 정상인지 아는 법

- `점검: 오류 0건, 장비 13대, 서버 12대, 케이블 87개, IP 78개`
- `build/report.md`의 최악 과가입비 1.18 : 1

### 점검 항목

IP 중복, 대역 밖 주소, 대역 겹침, 서버 끝자리 규칙(.11~ 컨트롤러 등), Ingress 노드가 한 랙에 몰림, 컨트롤러 같은 랙 배치, bond가 리프 한 대에 몰림, 스파인 같은 랙, 랙 전력 80% 초과, 리프 포트 부족.

### 막혔던 것

**Windows 콘솔에서 한글이 깨짐** — cp949 출력 때문. `main()`에서 `sys.stdout.reconfigure(encoding="utf-8")`.
