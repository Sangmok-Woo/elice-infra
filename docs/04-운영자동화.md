# 4단계 — 운영 자동화

## 목표

설정 반영과 상태 점검을 플레이북 하나씩으로 하고, 모니터링 대상이 원장에서 자동으로 채워진다.

---

## 뭐가 돌아가나

- **`automation/ansible/push-config.yml`** — 문법 검사(`vtysh -C`) → 파일 diff → `frr-reload.py --reload`(바뀐 줄만, 세션 유지) → BGP 복구 확인. 한 대씩, 실패하면 멈춤
- **`automation/ansible/check-fabric.yml`** — 기대 BGP 세션 수와 L2VNI 원격 VTEP 확인. 끊긴 이웃 이름을 찍어 줌
- **`monitoring/prometheus.yml`, `alerts.yml`** — ⚠️ 미확인. 랩에서 안 돌렸고 메트릭 이름은 수집기 버전에 맞춰 고쳐야 한다

### 띄우는 법 (랩 대상, WSL)

```bash
cd /root/labs/elice-infra/automation/ansible
/root/ansible-venv/bin/ansible-playbook -i ../../lab/generated/ansible-hosts.yml check-fabric.yml
/root/ansible-venv/bin/ansible-playbook -i ../../lab/generated/ansible-hosts.yml push-config.yml \
  --check --diff -l leaf3a -e config_dir=/root/labs/elice-infra/lab/generated
```

### 정상인지 아는 법

- check-fabric: 8대 failed=0. spine1 eth5를 내리면 `spine1: BGP 5/6 — 끊긴 이웃 ['eth5']`
- push-config `--check --diff`: 바뀔 줄만 `-`/`+`로 보이고 장비는 그대로
- 문법 틀린 설정은 `문법 검사` 단계에서 fatal

### 막혔던 것

**`frr-reload.py --test`로 변경 감지가 안 됨** — 바뀐 게 없어도 정규화 차이(`bgp log-neighbor-changes` 등)를 늘 출력한다. 감지는 Ansible copy의 파일 diff로, reload는 적용에만 쓴다.

**copy가 `/etc/frr/frr.conf`를 못 바꿈** — 랩에서 바인드 마운트 파일이라 원자적 교체 불가. `unsafe_writes: true`.
