# 3단계 — 랩 검증

## 목표

운영 설계와 같은 설정을 containerlab에 올려, 연결·격리·방화벽·장애를 명령 하나로 확인한다. `test.sh` 32항목 통과.

---

## 뭐가 돌아가나

- **스위치 8대** — FRR 10.2.1 컨테이너. 생성된 `frr.conf`, `interfaces.sh`를 그대로 씀
- **서버 12대** — 워커는 FRR 이미지(BGP로 VIP 광고, `python3 -m http.server`로 웹 응답), 나머지는 `hospnet-host`
- **fw1** — `fwlab-fw` 이미지 + 생성된 `rules.nft`
- **inet, bastion** — 인터넷 사용자와 관리자 흉내

실행 사본은 WSL `/root/labs/elice-infra/lab`.

### 띄우는 법

```bash
# Windows에서 배포판 붙잡아 두기
wsl -d Ubuntu -u root -- sleep infinity
# WSL 안에서
cd /root/labs/elice-infra/lab && ./deploy.sh && ./test.sh
./destroy.sh
```

### 정상인지 아는 법

- `결과: PASS 32 / FAIL 0`
- 장애 시험: 서버 링크 단절 손실 2/200, 스파인 다운 손실 0/200

### 운영 설계와 다른 점

포트명 ethN, bond는 active-backup(LACP+ESI-LAG 아님), 방화벽 1대, OOB·ISP 없음, QoS 미적용.

### 막혔던 것

**fw1이 계속 재시작** — `fwlab-fw` 이미지 엔트리포인트가 `/rules/step1-open.nft`를 읽다 죽는다. 토폴로지에 `entrypoint: sleep infinity`.

**FRR이 VRF보다 먼저 뜸** — `deploy.sh`가 `interfaces.sh` 뒤에 `vtysh -f /etc/frr/frr.conf`로 다시 읽힌다.

**FRR 이미지 ping에 `-M` 없음** — 점보 DF 시험은 iputils가 있는 `hospnet-host`(ceph, ctrl)에서 쏜다.
