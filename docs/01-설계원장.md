# 1단계 — 설계 원장

## 목표

랙, 장비, 서버, VLAN, VRF, IP 대역, 방화벽 정책이 전부 YAML 두 파일에 들어 있고, 다른 곳에는 설계 값이 없다.

---

## 뭐가 돌아가나

- **`inventory/site.yml`** — 설계의 원본. 랙 3, 스위치 11, 방화벽 2, 서버 12, VLAN 3, VRF 3, 대역 14개
- **`inventory/fw-policy.yml`** — 방화벽 규칙 9개 + NAT. 위에서부터 평가, 기본 차단

### 핵심 규칙 (원장에 박아 둔 것)

| 규칙 | 값 | 이유 |
|---|---|---|
| ASN | 스파인 65100(같은 값), 리프 65110+번호, K8s 65200 | 스파인끼리 같은 AS면 스파인 경유로 되돌아오는 경로가 AS 검사로 막힌다 |
| VNI | 10000 + VLAN | 외울 필요 없게 |
| RT | 65000:VNI 고정 | eBGP 패브릭에서 자동 RT는 리프마다 달라 서로 못 받는다 (clos-fabric에서 겪음) |
| 호스트 번호 | 컨트롤러 .11~, 워커 .21~, Ceph .31~ | 모든 VLAN에서 같은 끝자리 |
| MTU | 패브릭 9216, 스토리지 9000, 서비스 1500 | 서비스는 인터넷 경로와 맞춘다 |

### 고치는 법

서버 한 대 추가 = `servers:`에 한 줄.

```yaml
  - {name: wrk6, role: worker, rack: R3, host: 26}
```

### 막혔던 것

**Ceph 4대를 3랙에 고르게 못 나눈다** — 2/1/1이 되어 R1을 잃으면 일부 데이터가 복제본 2개를 동시에 잃는다. 원장으로는 못 풀고, 제안서 12장에 CRUSH 장애 단위를 랙으로 두는 안과 증설 계획(2/2/2)으로 적었다.
